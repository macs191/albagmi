# albagmi — Service Hub Desktop

تطبيق عربي لإدارة مواقع الخدمات والمبيعات والمصروفات، يعمل كواجهة ويب وكتطبيق Windows عبر Electron. صفحة الموقع العامة مخصصة لدخول حسابات المكاتب فقط. لوحة مدير النظام على `/max` وتتطلب كلمة مرور خادمية منفصلة؛ إخفاء الرابط ليس بديلًا عن كلمة مرور قوية. تحفظ بيانات التطبيق في Supabase لكل حساب بمفتاح يساوي Supabase Auth UID، وتستخدم الواجهة نسخة محلية مؤقتة مرتبطة بالـUID نفسه.

## الوظائف

- واجهة عربية RTL لمواقع الخدمات والبحث والتصنيفات والمفضلة.
- تسجيل المبيعات والمصروفات والتصفية حسب التاريخ وحساب الإجماليات.
- طباعة تقرير يومي للتاريخ المحدد على A4 عمودي، مع تفاصيل المعاملات والمصروفات وإجماليات اليوم والصافي.
- طباعة تقرير شهري على A4 أفقي، يعرض كل يوم في الشهر بما فيه الأيام التي لم تسجل فيها حركة.
- دخول المكاتب باسم المستخدم وكلمة المرور التي ينشئها المدير؛ لا يوجد تسجيل ذاتي.
- لوحة مدير منفصلة على `/max` لإنشاء حسابات المكاتب وتحديد بياناتها ومدد الاشتراك وتجديدها.
- تنبيه بعد انتهاء الاشتراك بمهلة خمسة أيام، ثم منع الدخول وقراءة/تعديل البيانات حتى التجديد.
- الإعدادات داخل حساب المكتب لا تحتاج كلمة مرور إضافية؛ وظائف إدارة مواقع المكتب باقية.
- فتح خدمات المكتب في تبويبات داخل التطبيق باسم الخدمة فقط، دون عرض عنوان الرابط أو تحويل المستخدم إلى المتصفح الخارجي.
- تعديل اسم المكتب مباشرة من الإعدادات، وإرسال طلب تغيير كلمة المرور ليوافق عليه المدير قبل تطبيقه.
- لوحة المدير تعرض طلبات تغيير كلمة المرور، وتتيح تحرير حساب المكتب أو حذفه نهائيًا بعد تأكيد اسم المستخدم؛ حذف الحساب يمحو بيانات المكتب وسجلاته عبر Supabase Auth UID.
- برنامج Windows يستخدم WebContentsView داخل نافذة واحدة، ويحفظ حالة صفحات الخدمات عند التبديل بينها؛ ويحتفظ ببيانات التصفح في جلسة Electron دائمة، ويدعم تنزيل ملفات الخدمة والطباعة ورفع الملفات ضمن صلاحيات الموقع نفسه.

## التطوير المحلي

```bash
pnpm install
pnpm dev
```

`pnpm dev` يشغّل واجهة Vite فقط ولا يشغّل Vercel Functions؛ لذلك لا يكفي وحده لاختبار تسجيل الدخول. استخدم `vercel dev` مع متغيرات البيئة أو اختبر الموقع بعد نشره على Vercel. صفحة `/api/health` تتحقق من إعدادات الخادم واتصال Supabase والجداول المطلوبة.

لضمان توجيه المسارات المتداخلة على Vercel، توجد نقاط دخول صريحة في ملفات `api/admin/` و`api/client/`، بما فيها مسارات طلبات كلمة المرور وإعدادات العميل، وتستخدم جميعها معالج الطلب المشترك `api/[...path].js`.

## Supabase ومتغيرات Vercel

يوجد جدول `public.albagmi_accounts` لحسابات المكاتب والاشتراكات وحالة التفعيل وعدّاد الدخول وآخر دخول، وجدول `public.albagmi_user_data` لحالة التطبيق ومبيعاته ومصروفاته، وجدول `public.albagmi_site_visitors` لمعرفات زوار عشوائية غير شخصية، وجدول `public.albagmi_password_change_requests` لطلبات تغيير كلمة المرور. يربط `user_id` في جدول بيانات التطبيق مباشرة بـSupabase Auth UID. تستخرج Vercel API الـUID من رمز الجلسة الموثق؛ ولا يقبل الخادم UID يرسله العميل لتحديد حساب آخر. الجداول محمية بـRLS والوصول الخادمي يستخدم `service_role`. طلب كلمة المرور ينتظر الموافقة ويُخزن مؤقتًا AES-GCM مشفرًا ثم يمسح السر المشفر بعد القرار.

في Vercel افتح **Project → Settings → Environment Variables** وأضف المتغيرات التالية. أضفها لبيئة **Production**، وأضفها أيضًا إلى **Preview** إذا كنت تختبر روابط المعاينة، ثم أعد النشر:

| الاسم | القيمة المطلوبة |
|---|---|
| `SUPABASE_URL` | عنوان Project URL لمشروع Supabase `macs` من إعدادات API. |
| `SUPABASE_ANON_KEY` | مفتاح `anon` أو `publishable` المقابل للمشروع نفسه. |
| `SUPABASE_SERVICE_ROLE_KEY` | مفتاح `service_role` السري من `macs`؛ خزّنه كمتغير خادمي سري فقط. |
| `ALBAGMI_ADMIN_PASSWORD` | كلمة مرور قوية وفريدة للوحة `/max`، وليست كلمة مرور المكتب. تجنّب الأرقام القصيرة أو الشائعة. |
| `ALBAGMI_ADMIN_JWT_SECRET` | قيمة عشوائية سرية لا تقل عن 32 بايت؛ يمكن توليدها بأداة أسرار موثوقة أو بالأمر `openssl rand -base64 48`. |

لا تضف بادئة `VITE_` إلى أي سر. المتغير `ALBAGMI_ALLOWED_ORIGINS` اختياري لموقع الويب المنشور على نفس نطاق Vercel ولا يحتاج إعدادًا عادةً. للـEXE المنشور مع `file://` اجعل قيمة المتغير `null` في Vercel للسماح بطلبات التطبيق المحلي فقط؛ لا تستخدم `*`.

لا تضبط `VITE_API_BASE_URL` لموقع الويب على Vercel؛ اتركه غير مضبوط ليستخدم الموقع مسارات `/api` من النطاق نفسه. هذا ليس سرًا، ويُستخدم فقط وقت **بناء نسخة Electron** كعنوان كامل لموقع Vercel المنشور. إذا ضُبط على عنوان placeholder أو نطاق غير صحيح، قد يظهر `Network Error`.

## دخول المدير والاشتراكات

يدخل مدير النظام من `https://نطاق-موقعك/max` بكلمة مرور `ALBAGMI_ADMIN_PASSWORD`. صفحة `/` مخصصة لحسابات المكاتب ولا تعرض خيار دخول المدير. تبدأ مدة الاشتراك عند إنشاء/تفعيل حساب المكتب بواسطة المدير، ويُسجل الخادم وقت البداية في `subscription_started_at`؛ لا تنتظر المدة أول دخول للعميل. بعد الانتهاء يُسمح بالدخول خلال مهلة التجديد البالغة خمسة أيام، ثم يمنع الخادم الدخول وقراءة أو تعديل البيانات حتى يجدد المدير الاشتراك.

## تشخيص Network Error

من شاشة الدخول اضغط **فحص اتصال الخدمة**. إذا تعذر الوصول إلى `/api/health` فتحقق من نشر دوال API وأن رابط الويب يستخدم النطاق نفسه. إذا ظهرت متغيرات ناقصة، أضفها إلى Vercel ثم أعد النشر. إذا تعذر الاتصال بـSupabase، راجع `SUPABASE_URL` و`SUPABASE_ANON_KEY` و`SUPABASE_SERVICE_ROLE_KEY`، وتأكد أن الجداول `albagmi_accounts` و`albagmi_user_data` و`albagmi_site_visitors` و`albagmi_password_change_requests` موجودة.

إذا كان الخطأ في نسخة Electron، ابنِ البرنامج مع `VITE_API_BASE_URL` مضبوطًا على عنوان Vercel المنشور، وأعد بناء EXE بعد تغييره. لا تستخدم `pnpm dev` وحده لاختبار API.

## نسخة Electron لنظام Windows

بعد نشر API على Vercel، عرّف `VITE_API_BASE_URL` بعنوان النشر الكامل **في بيئة بناء Electron فقط**، ثم نفذ الأمر لإنشاء مثبت Windows يضيف اختصارًا لسطح المكتب وقائمة ابدأ:

```bash
pnpm package:win
```

تسجيل المدير في Electron متاح عبر المسار المحلي `#/max`، بينما رابط الويب هو `/max`. يتصل التطبيق من `file://` بعنوان Vercel فقط، لذلك يجب إعداد `ALBAGMI_ALLOWED_ORIGINS=null` في Vercel. تعرض المواقع في WebContentsView داخل النافذة نفسها؛ يحفظ Electron ملفات التنزيل في مجلد Downloads، ويدعم تحديد ملفات الرفع والطباعة. يحتفظ التطبيق بنوافذ المواقع المخفية عند التبديل حتى لا يعيد تحميل صفحاتها، ويحفظ ملفات الارتباط عبر الجلسة الدائمة. لا يفتح النوافذ المنبثقة في متصفح النظام. بعض المواقع قد تمنع العرض داخل الإطارات أو تتطلب نوافذ منبثقة؛ لا يتجاوز التطبيق سياساتها.

## إدارة حسابات المكاتب والإحصاءات

من `/max` يستطيع المدير تعديل اسم المستخدم واسم المكتب واسم المالك ورقم الهاتف، وإدخال كلمة مرور جديدة اختيارية؛ تبقى خانة كلمة المرور فارغة افتراضيًا ولا تُعرض أو تُحفظ كلمة المرور الحالية. تغيير اسم المستخدم يحدّث البريد الداخلي في Supabase Auth والاسم في سجل المكتب. يمكن للمدير إيقاف الحساب أو إعادة تفعيله، ويُرفض تسجيل الدخول والطلبات المحمية للحساب الموقوف.

تعرض اللوحة الحسابات النشطة والواقعة في مهلة التجديد، وعدد مرات الدخول الناجحة لكل حساب وآخر وقت دخول. يبدأ عدّ الدخول عند نشر التحديث ولا توجد بيانات تاريخية موثوقة قبل ذلك. عدد الزوار هو عدد تقريبي لمعرّفات متصفحات فريدة منذ التفعيل، وليس عدد أشخاص مؤكّد؛ لا يخزّن النظام IP أو الاسم أو البريد. حذف بيانات المتصفح أو استخدام جهاز آخر قد ينتج معرّفًا جديدًا.

لا تحتاج هذه الإضافات إلى متغير بيئة جديد. يلزم نشر migration المضافة إلى Supabase `macs` قبل نشر إصدار الواجهة/API الذي يستخدم حقول النشاط والإحصاءات.

بعد نشر migration `20261030195600_add_password_requests_and_explicit_account_deletion.sql` تصبح طلبات كلمات المرور والحذف النهائي متاحة. عند موافقة المدير يرسل الخادم كلمة المرور الجديدة مباشرة إلى Supabase Auth ثم يمسح النسخة المشفرة. الحذف النهائي من لوحة المدير يتطلب كتابة اسم المستخدم حرفيًا ويمحو حساب Auth وجدول المكتب وبيانات UID والطلبات المرتبطة؛ لا يمكن استعادة البيانات بعده.

اسم مثبت Windows هو `ServiceHub-Desktop-0.1.2-Setup.exe`. يستخدم بناء Electron مسارات أصول نسبية، وينشئ اختصارًا على سطح المكتب وقائمة ابدأ؛ يستضاف EXE على GitHub Releases ويشير زر الويب إلى أصل الإصدار. لا تحفظ نسخة التثبيت في تاريخ Git العادي. يلزم شهادة توقيع Windows صالحة من جهة إصدار موثوقة لإزالة تحذير الناشر غير المعروف؛ لا توجد شهادة توقيع مضمنة في المشروع.
