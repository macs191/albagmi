# albagmi — Service Hub Desktop

تطبيق عربي لإدارة مواقع الخدمات والمبيعات والمصروفات، يعمل كواجهة ويب وكتطبيق Windows عبر Electron. صفحة الموقع العامة مخصصة لدخول حسابات المكاتب فقط. لوحة مدير النظام موجودة على `/max` وتتطلب كلمة مرور مستقلة؛ المسار غير ظاهر في واجهة المكاتب، لكنه ليس بديلًا عن كلمة مرور قوية. يحفظ التطبيق بيانات كل مكتب في Supabase، مع نسخة محلية مؤقتة على الجهاز.

## الوظائف

- واجهة عربية RTL للصفحة الرئيسية ومواقع الخدمات والبحث والتصنيفات والمفضلة.
- تسجيل المبيعات والمصروفات والتصفية حسب التاريخ وحساب الإجماليات.
- دخول المكاتب باسم المستخدم وكلمة المرور التي ينشئها المدير؛ لا يوجد تسجيل ذاتي.
- صفحة مدير منفصلة على `/max` للدخول بكلمة مرور خادمية فقط، وإنشاء حسابات المكاتب وتحديد بياناتها ومدد الاشتراك وتجديدها.
- تنبيه بعد انتهاء الاشتراك بمهلة خمسة أيام، ثم منع الدخول والوصول للبيانات من الخادم حتى التجديد.
- الإعدادات داخل حساب المكتب لا تتطلب كلمة مرور إضافية؛ تبقى وظائف إدارة مواقع المكتب كما هي.

## التطوير المحلي

```bash
pnpm install
pnpm dev
```

`pnpm dev` يشغّل واجهة Vite فقط، ولا يشغّل Vercel Functions. لذلك لن يعمل تسجيل الدخول الكامل على `localhost` بهذا الأمر وحده. استخدم `vercel dev` مع متغيرات البيئة، أو اختبر على موقع منشور على Vercel. صفحة `/api/health` تفحص توافر الدالة، إعدادات الخادم، اتصال Supabase، وجدول الحسابات.

## ربط Supabase وVercel

المستودع يحتوي API خادمية في `api/[...path].js` وملف SQL للمخطط في `supabase/migrations/`. يوجد جدول مستقل اسمه `public.albagmi_accounts` مع RLS في مشروع Supabase `macs`؛ جداول المشروع وبياناته السابقة لم تُحذف أو تُفرّغ أو تُعدّل. ملف `vercel.json` يعيد توجيه `/max` إلى تطبيق الواجهة، ولا يتضمن قاعدة إعادة توجيه عامة لمسارات API.

اربط مستودع GitHub بـVercel، ثم أضف المتغيرات الخادمية من `.env.example` إلى إعدادات المشروع على Vercel. استخدم URL وpublishable/anon key ومفتاح service role من مشروع `macs`. اترك `VITE_API_BASE_URL` غير مضبوط لموقع الويب حتى يستخدم `/api` على نفس النطاق؛ ضبطه على placeholder أو نطاق نشر آخر قد يسبب `Network Error`. خزّن `SUPABASE_SERVICE_ROLE_KEY` وكلمة مرور المدير و`ALBAGMI_ADMIN_JWT_SECRET` كمتغيرات خادمية فقط؛ لا تضعها في أسماء تبدأ بـ`VITE_` ولا تضفها إلى Git أو ملف EXE. استخدم كلمة مرور طويلة وعشوائية، ثم أعد النشر بعد إضافة المتغيرات.

المدير يدخل من `https://نطاق-موقعك/max` بكلمة المرور المحددة في `ALBAGMI_ADMIN_PASSWORD`. الرابط المخفي طبقة تنظيمية فقط؛ حماية الإدارة الفعلية تعتمد على كلمة المرور والتحقق الخادمي. صفحة `/` لا تعرض خيار دخول المدير.

مهم أمنيًا: لا تعتمد على مسار `/max` كوسيلة حماية ولا تستخدم رمزًا رقميًا قصيرًا وحده؛ استخدم كلمة مرور طويلة وفريدة. محدد المحاولات في API يعمل داخل ذاكرة نسخة Vercel الحالية فقط، لذلك هو best-effort وليس عدّادًا دائمًا مشتركًا بين كل النسخ. فعّل كذلك حماية/تحديد معدل الطلبات على مستوى مزود الاستضافة عند توفرها.

## تشخيص Network Error

من شاشة الدخول اضغط **فحص اتصال الخدمة**. إذا ظهر خطأ عدم الوصول إلى `/api/health`، فتحقق أن دوال Vercel نُشرت مع الواجهة وأن صفحة الويب تستخدم أصل النطاق نفسه للـAPI. إذا ظهرت أسماء متغيرات ناقصة، أضفها إلى Vercel ثم أعد النشر. إذا أظهر الفحص تعذر اتصال Supabase، راجع `SUPABASE_URL` و`SUPABASE_ANON_KEY`، ومفتاح الخدمة وجدول `albagmi_accounts`.

إذا كان الخطأ في نسخة Electron، ابنِ البرنامج مع `VITE_API_BASE_URL` مضبوطًا على عنوان Vercel المنشور. ولأن `file://` يستخدم أصلًا معتمًا، اسمح بطلبات Electron عبر `ALBAGMI_ALLOWED_ORIGINS` في Vercel؛ استخدم `*` أو قائمة origins صحيحة. لا تستخدم `pnpm dev` وحده لاختبار API.

## نسخة Electron لنظام Windows

بعد نشر API على Vercel، عرّف `VITE_API_BASE_URL` بعنوان النشر الكامل في بيئة البناء، ثم نفذ:

```bash
pnpm package:win
```

تسجيل المدير في Electron متاح عبر المسار المحلي `#/max`، بينما رابط الويب هو `/max`. أعد بناء EXE بعد تغيير رابط API.

## سياسة الاشتراك

يتحقق الخادم من صلاحية الاشتراك عند الدخول وكل طلب قراءة أو حفظ. بعد انتهاء الاشتراك تظهر رسالة تحذير بأن أمام العميل خمسة أيام للتجديد؛ وبعد نهاية المهلة يرفض الخادم الدخول وقراءة أو تعديل بيانات الحساب. التجديد يضيف الأيام إلى تاريخ الانتهاء الحالي إذا لم يكن قد مضى، أو يبدأ من اليوم إذا انتهى سابقًا.
